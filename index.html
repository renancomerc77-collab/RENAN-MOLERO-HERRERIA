MOTTA — Peças e Serviços para Caminhões

Sistema web com API própria para gerenciar clientes, veículos, peças, serviços e ordens de serviço. Projeto da disciplina de Programação Web e Mobile.

Problema

Uma loja de peças e serviços para caminhões lida com muita informação ao mesmo tempo: quem são os clientes, quais veículos eles têm, quais peças existem em estoque, quais serviços são oferecidos e quais ordens de serviço estão abertas. Sem um sistema único, esses dados ficam espalhados e difíceis de acompanhar.

[Confirme ou ajuste este texto: para quem era o sistema e por que isso importava no trabalho da disciplina.]

O que eu fiz

Desenvolvi um sistema web com tela de login e cadastro de usuários, e telas para cadastrar, consultar, editar e excluir clientes, veículos, serviços, peças e ordens de serviço. A tela inicial mostra quantos registros existem em cada cadastro. Os dados são guardados em um banco de dados, por meio de uma API que eu mesmo construí.

Como eu fiz

O projeto tem duas partes que se comunicam por uma API REST:

  • Front-end: React 19 com Vite. Um componente de CRUD reaproveitado em todas as telas, selects que buscam clientes e veículos para montar as ordens de serviço, e sessão do usuário mantida no navegador.
  • Back-end: Node.js com Express 5 e TypeScript, com rotas GET, POST, PUT e DELETE para cada cadastro. Validação dos dados recebidos com Zod, tratamento de erros em um middleware e senhas armazenadas com hash (bcryptjs).
  • Banco de dados: MySQL, acessado pelo Prisma ORM, com relacionamentos entre clientes, veículos e ordens de serviço.
  • Testes: as rotas da API foram testadas no Insomnia.

Resultado

  • 5 cadastros com CRUD completo: clientes, veículos, serviços, peças e ordens de serviço.
  • Login e criação de conta funcionando, com bloqueio de usuários inativos e senhas protegidas por hash.
  • Ordens de serviço ligadas a um cliente e a um veículo cadastrados.
  • Painel inicial com a contagem de registros de cada cadastro.
